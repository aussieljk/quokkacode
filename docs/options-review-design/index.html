Reviewing design options

A design pass for comparing images and sending a choice or notes back to an agent. These are local HTML mockups using the four account-picker images. Nothing here sends a message or changes Quokka Code.

A. A separate comparison window

Room for two images and notes. Resize it or make it full screen. The thread stays one click away.

B. A panel beside the thread

The conversation stays visible. Comparing two images squeezes both of them. An Open in a window button gives them more room.

I recommend A

A compact transcript card opens a resizable native window belonging to that review. It can use the whole screen, and you can return to the thread without losing your place or notes. A sheet would still be limited by the parent window and would block the conversation.

Start with a grid to scan the options, then compare a pair or view one alone. Fit shows the whole image; 100% gives a readable, scrollable view. Both are useful because fitting a wide mockup into half a screen still makes its text small.

What the built version would do

  • The agent calls show_options with a title and stable IDs, image paths, titles and a short note for each option. Reference images can be marked separately.
  • A compact review card stays outside collapsed tool groups. The thread moves to Needs you, like a question. The agent can finish its turn; the review survives the app closing or the runner restarting.
  • Picking an option and writing notes saves a draft. Closing the review keeps it pending. Send reply commits the choice and all notes together, then delivers one reply to the agent, resuming it if needed.
  • You can send notes without picking anything. An answered card shows the choice and can reopen the images and notes.

First build

Images, grid / 2-up / single, Fit / 100% with scrolling, arrow keys, per-image notes, one optional pick, a saved draft, and one reply. Persist copies of the images with the review so later edits to the source files do not change what was reviewed. Add HTML previews later, using the same review model. Overlays can wait until there is a real need for them.
